# SDP — Style Distillation Pipeline 方法论总览

## 命名

**SDP** = Style Distillation Pipeline，风格蒸馏流水线。

## 设计哲学

**风格不是特征的堆砌，而是特征之间的关系。**

一个作者的风格不在于"用了短句"，而在于"在什么情境下用短句、与什么搭配、产生什么效果"。因此 SDP 的核心不是提取孤立特征，而是提取**特征的使用模式**。

## 与 book2skill 方法论的根本差异

| 维度 | RIA-TV++ (book2skill) | SDP (author2skill) |
|---|---|---|
| 提取对象 | 方法论单元（可原子化） | 风格指纹（不可原子化） |
| 验证标准 | 预测力 + 独特性 | 稳定性 + 排除干扰 + 可操作性 |
| 输出数量 | 多个 skill | 一个 skill |
| 输出格式 | RIA++ 六段 | 风格档案 + 仿写指南 |
| 测试方式 | trigger 匹配测试 | 仿写对比 + 人工评审 |

## 流水线

```
┌─────────────────────┐
│ 阶段 0: 样本采集     │  选取代表段落 + 初读
└─────────┬───────────┘
          │ SAMPLES.md
          ▼
┌─────────────────────┐
│ 阶段 1: 六维并行提取 │  6 个 sub-agent 同时跑
└─────────┬───────────┘
          │ candidates/ (6 类)
          ▼
┌─────────────────────┐
│ 阶段 2: 交叉验证     │  稳定性 / 排除干扰 / 可操作性
└─────────┬───────────┘
          │ verified-features.md
          ▼
┌─────────────────────┐
│ 阶段 3: 风格档案合成 │  STYLE_PROFILE.md ← 用户确认
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│ 阶段 4: Skill 构造   │  SKILL.md (内置模板格式)
└─────────────────────┘
```

## 六维提取模型

风格档案由六个维度构成，每个维度有独立的提取 sub-agent:

| 维度 | 代号 | 关注点 | 类比 |
|---|---|---|---|
| 韵律 | P | 句长、节奏、段落呼吸 | 音乐的节拍 |
| 词汇 | L | 词频、词层、偏好/回避 | 画家的色盘 |
| 叙事 | N | 视角、时态、信息释放 | 摄影机角度 |
| 对话 | D | 占比、归因、角色声音 | 演员的台词 |
| 母题 | T | 主题、哲学、意象系统 | 交响乐的主旋律 |
| 签名 | S | 句式、场景、反模式、手法 | 艺术家的签名笔触 |

**关键设计**: 六维不是独立的——签名维度是前五维的"交叉验证"。一个特征如果同时出现在多个维度中，那它就是真正的风格核心。

## 不变量

1. **样本为王**: 没有文本样本就不能蒸馏，宁可停下来问用户
2. **可操作性**: 每条特征必须能转化为"要怎么做"的指令
3. **反模式同等重要**: "不要做什么"往往比"要做什么"更能定义风格
4. **用户参与**: 阶段 0 和阶段 3 必须暂停等用户确认
5. **整体性**: 风格是一个整体指纹，不要试图拆成多个独立 skill
